# 닉네임 보정과 재현 범위

사용자가 제공한 `ァÐぎ★` 화면을 기준으로 로컬 폰트에서 직접 렌더링한 결과를 비교했습니다. 정답 코드포인트는 `U+30A1 U+00D0 U+304E U+2605`입니다. 게임 해상도는 1920×1080이며 확대 샘플은 UI 100%입니다. 화면 원본, 폰트 바이너리, 문자별 비트맵 아틀라스는 저장소에 넣지 않습니다.

## 원래 크기의 획 마스크

| profile | 렌더링과 배치 | 마스크 크기 |
| --- | --- | --- |
| `dotum` | 돋움 face 2·11px·1비트. 전체 문자열을 먼저 렌더링하고 공통 세로 위치를 보존한 채 네 획 영역 사이를 1px로 맞춥니다. | 31×8px |
| `nanum-neo` | `ァÐぎ`는 궁서 face 2·12px·1비트·가로 1px 굵게, `★`는 나눔스퀘어 네오 Bold face 0·11px·그레이스케일입니다. | 37×12px |

나눔스퀘어 네오 조합의 잘라낸 글리프 좌상단 좌표는 순서대로 `(0, 5)`, `(9, 2)`, `(18, 0)`, `(26, 1)`입니다. 겹치는 획의 alpha는 최댓값으로 합칩니다. 이 좌표와 돋움의 획 영역 분리는 해당 네 글자에만 맞춘 조건입니다.

## 화면 비교 실험의 의미

돋움의 원래 크기 획 마스크 88픽셀은 제공된 작은 원본의 청록색 획과 모두 일치했습니다. 확대 화면에서는 배경에서 추정한 획 alpha에 공통 배율·이동량을 맞췄을 때 돋움 약 0.918, 나눔스퀘어 네오 조합 약 0.925의 IoU를 얻었습니다. 임계값은 alpha 0.5이며 같은 화면에 맞춘 결과입니다. 독립 평가 데이터나 OCR 인식 정확도가 아닙니다.

이 패키지는 확대 전 마스크를 보존하되 crop 안의 위치를 고정하고 `dfragon` 모델의 배율(1080px·UI 100%에서 1.8)을 사용자가 선택하도록 합니다. 이전 실험의 1.805배 및 소수 픽셀 이동량 탐색은 수행하지 않습니다. 따라서 위 IoU는 패키지의 모든 출력에 적용되는 보장 수치가 아닙니다.

궁서와 궁서체의 12px·13px은 이 세 문자에서 같은 비트맵을 냈습니다. 게임 내부 폰트 선택 API, 정확한 face·크기, 임의 문자열의 대체 규칙은 확인하지 않았습니다. `metrics` 모드의 advance·공통 baseline 배치와 나눔 미지원 문자의 궁서 fallback은 후속 실화면 검증이 필요한 가설입니다.

## dfragon 호환성 확인

참조 revision `919c547f3b0f9c0eb510a9b334eaa469764a7aeb`의 `packages/lib/src/index.ts`, `packages/lib/src/cp949-characters.ts`, `packages/lib/src/dnf-ui-scale.ts`, `packages/lib/test/nickname.test.mjs`를 확인했습니다.

Python 표준 codec의 CP949 왕복 문자 집합과 참조 표를 BMP 전체에서 대조했습니다. 한글 완성형을 포함한 비ASCII 문자 17,048개가 일치했고 차이는 0개였습니다. 이 문자 집합 중 Unicode default-ignorable 문자는 `U+00AD`, `U+3164` 두 개였으며 별도로 거절합니다. 정적 문자 표와 TypeScript 런타임 의존성은 패키지에 추가하지 않았습니다.

자동 테스트는 12바이트 경계, 원본 문자 유지, 공백·보이지 않는 문자·미지원 Unicode, 호출자 금칙어, UI 배율, 실제 폰트 coverage와 fallback, 두 원본 크기 마스크, PNG 메타데이터, CLI 출력을 확인합니다. 폰트가 없는 환경의 skip을 실제 폰트 렌더링 성공으로 해석하면 안 됩니다.
